## Context

`PptxCodec.ReorderSourceSlideIdList` already moves exact cloned `p:sldId`
records and preserves SlideParts, relationships, opaque descendants, and native
slide IDs. PPJ currently blocks before this writer because projection names a
page from `presentation/slide/{position}` and names its elements from the same
position-derived owner.

## Goals / Non-Goals

**Goals:**

- Keep page and page-local element IDs stable when a retained source page moves.
- Represent page order only through the existing ordered `pages` array.
- Reuse the native source-binding and post-write validation path.
- Keep comments, custom shows, and modeled sections bound to the same pages.

**Non-Goals:**

- Page insertion or source-slide cloning.
- Element z-order identity redesign.
- Repairing opaque section extensions.
- Assigning a new global object identity to malformed duplicate native IDs.

## Decisions

### 1. SlidePart is the imported page identity anchor

Projection derives the PPJ page ID from the source SlidePart path. That path is
stable when only `p:sldIdLst` order changes and is already independently bound
by the source hash, relationship ID, and slide XML hash.

### 2. Element IDs retain only their page-local path

The wire artifact may continue using position-oriented internal IDs. PPJ strips
the slide-owner prefix and combines the remaining local `element/...` path with
the stable page ID. Moving a whole page therefore preserves all of its element
IDs without changing the Office wire.

### 3. Reorder remains declarative

The Agent changes `pages[]` order. Each capable page advertises
`reorder/pageOrder`; there is no command log or operation list. The compiler
requires a complete unique permutation of retained pages and delegates the
actual mutation to the native source-preserving exporter.

### 4. Section semantics stay explicit

When modeled sections exist, their `pages` arrays must still form a complete
ordered partition after the page move. An Agent may update the boundary in the
same PPJ transaction. An opaque section graph prevents reorder capability from
being issued.

The native writer applies a capable modeled section update against the original
slide order, verifies it against the requested stable page order, and only then
moves the exact `p:sldId` records. This avoids a transient invalid partition
being re-read as opaque between the two changes.

## Risks / Trade-offs

- [Stable IDs collide] -> Include the stable page ID and retain the complete
  owner-local element path; continue using deterministic collision handling.
- [Reorder invalidates a section partition] -> Let PPJ semantic validation and
  `PptxSectionCodec` reject the transaction rather than normalizing it.
- [A source binding is stale] -> Reproject the exact input and require unchanged
  nativeRefs before lowering.

## Migration Plan

Imported PPJ generated by this version uses stable source-derived page IDs.
Existing saved PPJ remains tied to its original source projection and is not
silently rewritten. Source-free PPJ is unchanged.
