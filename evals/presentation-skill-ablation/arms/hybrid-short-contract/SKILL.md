# Presentations — concise contract route

This experimental route combines a short Kimi-style entry with a compact
What/What-kind decision and the production fidelity gates. Read the shared
[invariants](../../common/invariants.md) first; nothing in this route weakens
those contracts.

## Route

1. **What, in one line** — write `audience → change → one claim → evidence
   boundary → delivery mode` in the PPJ intent. Name the page responsibility
   and the protected evidence before drawing.
2. **What-kind, in one line** — choose one primary scenario, one design source,
   and the `reader`, `hybrid`, or `live` mode. Read exactly that scenario guide
   from `../../common/references/scenarios/`. A design system or selected
   template is authority; otherwise choose a self-directed direction.
3. **How, locally** — create the task-local [style brief](../../common/style-brief.md)
   before adding elements. It must name the visual thesis, carrier, visual move,
   reading order, visual DNA, avoid-list, and render probes. It is a decision
   record, never a page skeleton or component library.

## Compose or edit

Read [PPJ](../../common/references/ppj.md), then load only the carrier-specific
references: fonts/text, shapes/lines, charts/tables, image/layers, motion,
components/templates, or imported native references. Write one strict `.ppj`
program with stable IDs and true back-to-front element order. Do not use
MJS/JSX, raw OOXML, XPath, relationship IDs, or another authoring engine.

For every page, let the claim's relationship choose the carrier. Keep chart
labels, lines, markers, numbers, sources, image subjects, and connectors
visible. Preserve truthful shared plots; do not invent a trend or separate a
real relationship just to silence a checker. For two observed endpoints, use
the explicit endpoint-comparison route.

If an image is needed, use the shared `officekit image` flow and record query,
candidate, hash, rights, crop/focus, and alt text. Images must carry evidence,
identity, explanation, or deliberate atmosphere; never fill an empty region.

For an existing PPTX, import it with `officekit ppj import`, read
`../../common/references/imported-native-ref.md`, and edit only issued typed or
`nativeRef` capabilities. Perform semantic edit before visual/delivery edit.
Preserve source hash, opaque objects, stable IDs, z-order, and non-target parts;
unsupported or stale mutations fail closed.

## Non-optional proof loop

```text
check → build → render at final size → inspect → repair the smallest layer
→ review → deliver
```

Treat overflow, clipping, unreadable type, false continuity, evidence
occlusion, label collision, bad crop/contrast, and accidental empty regions as
blocking defects. A render or review failure requires a local repair and a new
render, not extra decoration. For imported edits, re-import and audit stable
IDs, source binding, and non-target preservation. Never call structural or
render evidence PowerPoint playback evidence.

Return absolute PPJ/PPTX paths, hashes, review status, and honest playback
evidence. This is an experimental arm and does not select the production
default.
