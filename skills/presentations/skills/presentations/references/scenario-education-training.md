# Scenario: education and training

## Audience task

Help learners build a mental model, practice a procedure, or transfer a skill
they can use after the session. Lock the entry level, observable learning
outcome, practice condition, feedback rule, and after-use.

The deck is not the lesson by itself. It must support explanation, practice,
retrieval, and reference in the delivery mode the user selected.

## Narrative

Start from prior knowledge and the learning outcome. Sequence concept, example,
guided practice, feedback, application, and recap. Reveal complexity only after
the foundation is stable. Use misconceptions and failure states when they help
the learner discriminate, not as decorative warnings.

## Density and rhythm

Keep teaching pages focused and alternate explanation with demonstration or
practice. Use repetition for retrieval, not for visual cloning. Put detailed
reference material in handout-friendly pages or an appendix. In live delivery,
notes may hold prompts and answer timing; the visible page must not leak an
answer before the intended reveal.

## Visual carriers and archetypes

- concept map or annotated model;
- worked example with progressive annotation;
- correct/incorrect or before/after comparison;
- numbered procedure with visible state changes;
- screenshot or image with focused callouts;
- practice prompt followed by answer rationale;
- recap map, transfer checklist, or job aid.

Use diagrams for mental models and processes, screenshots for actual interface
states, tables for compact references, and charts only when interpreting data
is part of the skill. Images should support recognition or context, not fill
space.

## Visual grammar

Use consistent cues for definition, example, warning, action, and learner task.
Connectors and numbering must reveal sequence. Favor diagrams, highlighted
excerpts, and annotated screenshots over paragraphs inside decorative cards.

Typography and spacing should distinguish instruction, example, learner action,
and feedback. Surface roles may show state changes, but avoid turning the deck
into a simulated application UI. Motion may stage a process in live delivery;
the static page remains understandable.

## Avoid

Lecture transcripts, unexplained jargon, quiz answers visible too early,
arbitrary clip art, tiny multi-step screenshots, decorative progress bars, and
recaps that merely repeat section titles.

## Review questions

- Is the learner outcome observable and practiced?
- Does each page build on knowledge already introduced?
- Are examples representative, legible, and explained?
- Can the deck function as the promised handout or job aid afterward?
- If a page is hard to learn from, should the example, sequence, or carrier be
  repaired before style and motion?
