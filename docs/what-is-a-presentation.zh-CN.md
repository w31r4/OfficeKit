# OfficeKit 所说的演示文稿是什么

OfficeKit 不把 PPT 看成一组套好样式的页面。它同时是一次沟通活动、一份可编辑
deck、现场播放时随时间展开的体验，以及会继续被评审、修改、复用和归档的原生产物。

这个定义决定 Presentations Skill 如何规划、构图、复核和交付 PowerPoint。

[English](what-is-a-presentation.md)

## 先确定受众要发生什么变化

用户很少只是想要若干页面。他通常希望受众知道、理解、相信、决定、对齐、学会、
汇报、行动，或者留下可以继续使用的正式记录。

OfficeKit 因此先回答四个问题：

1. 受众是谁？
2. 看完后，他们必须发生什么变化？
3. 哪些证据支持这种变化？
4. 这份 deck 如何传递，会后还要怎么使用？

答案共同决定叙事、密度、视觉语言、备注、动效和原生结构。风格不能替代论证。

## 一份演示文稿有四种相连的形态

| 形态 | OfficeKit 的职责 |
| --- | --- |
| 沟通活动 | 保留受众、目的、期望结果、证据和决策边界。 |
| 可编辑 deck | 建立可以评审、修改、重排和复用的有序页面与对象。 |
| 播放体验 | 只在有助于传递时使用节奏、转场、动画、备注和注意力引导。 |
| 原生产物 | 保留能重新打开、渲染、编辑并进入后续工作的真实 PowerPoint 结构。 |

一张漂亮截图并不等于合格 PPT：如果文件难以编辑、继承结构丢失或无法继续迭代，
它仍然是不完整的。反过来，技术上有效的文件如果不能帮助受众完成任务，也不算成功。

## 传递方式会改变设计

OfficeKit 区分三种主要模式：

- **Live**：由演讲者控制节奏，强调远距离可读性、视觉焦点、分步揭示和演讲备注；
- **Reader**：deck 必须能够独立解释，页面需要更多上下文、可追溯证据和导航，减少只为现场服务的效果；
- **Hybrid**：同时服务现场和阅读，但必须明确哪一种优先，再用备注、附录或补充页面服务另一种。

会后用途同样重要：它可能成为决策记录、讲义、参考件或下一份材料的复用来源。
这些用途会影响引用、备注、可编辑性以及页面必须保留多少上下文。

如果 PPT 对主要任务的适配度较弱，OfficeKit 会记录限制；当用户明确要求 PPT 时，
仍然继续生成，不会擅自改成交付文档、仪表盘或网页。

## 场景与设计机制是两件事

场景描述组织为什么做这份 PPT。OfficeKit 覆盖七类常见场景：分析决策、商业提案、
经营汇报、学术研究、教育培训、技术工程和品牌创意。

设计机制描述信息如何组织和表现，例如编辑式克制、数据复盘、技术架构、视觉叙事、
学术证据或品牌发布。一个场景可以组合多个机制；两者都不是模板或固定配色。

每次新建 deck，Agent 都要确定主场景、设计权威、项目专属方向，并在构图前写出
具体的视觉语法。

## 设计权威有明确顺序

OfficeKit 识别四种设计来源：

1. 用户提供的模板或参考文件；
2. 明确的品牌规范或设计系统；
3. 基于可观察证据的风格迁移；
4. 针对任务形成的自主设计。

权威来源优先。场景指南可以补充未定义的选择，但不能覆盖模板已经证明的字体、层级、
几何、资产和其他规则。模板之所以有价值，是因为它保存了会重复出现的决定；没有模板
也可以形成好设计。

## 质量至少有六层

| 层次 | 复核问题 |
| --- | --- |
| 事实 | 论断、数值、来源和概念区分是否正确、可追溯？ |
| 沟通 | 受众、期望变化和行动要求是否清楚？ |
| 叙事 | 页面顺序是否形成预期的理解、判断或决策？ |
| 认知 | 受众能否在不过载的情况下感知、比较并连接信息？ |
| 视觉 | 层级、字体、图像、数据图形、间距和动效是否服务含义？ |
| 原生与运行 | 文件能否重新打开、继续编辑、保留必要结构、可靠播放并支持复用？ |

不同层次需要不同证据。包结构检查不能证明事实，对象数量不能证明审美，紧凑文本视图
不能证明裁剪、对比度、视觉平衡和播放效果。OfficeKit 分开记录确定性检查、Agent 判断、
视觉复核和原生宿主证据。

## OfficeKit 负责什么

Agent 决定采取什么立场、传达什么信息。OfficeKit 教它如何把这些决定编译成连贯的
原生演示文稿，检查确定性约束，保存任务状态，并明确报告能力边界。

OfficeKit 不承诺万能审美评分、自动事实真相、一次生成完美成品，也不取代人的判断。
它交付的是一份强健、可检查、可编辑，并且可以继续通过对话改进的工作产物。
